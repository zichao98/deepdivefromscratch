Containers 101

A container packages your application with everything it needs — code, runtime, libraries, and config — so it runs the same way on your laptop and in production.

Why containers beat virtual machines (VMs)

Virtual machines each run a full guest operating system (OS) on top of a hypervisor. That means heavy disk usage, slow boot times, and a big resource tax.

Containers share the host operating system (OS) kernel and isolate processes using Linux features like cgroups and namespaces. They are lightweight, fast, and portable.

Key container concepts

  • Image — a read-only template with layers.
  • Container — a runnable instance of an image.
  • Registry — a store for images (Docker Hub, Quay, etc.).
  • Open Container Initiative (OCI) — the open standard that makes Docker and Podman images compatible.

Docker vs Podman

Both Docker and Podman build and run Open Container Initiative (OCI)-compliant images. The biggest difference is architectural: Docker uses a central daemon; Podman is daemonless and rootless by default.

Build & Run a Container

You describe an image in a Dockerfile or Containerfile, build it into an image, then run it as a container.

Dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["node", "server.js"]
Containerfile (Podman)
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["node", "server.js"]

The two files look identical because they both follow the Open Container Initiative (OCI) image format. Podman prefers the name Containerfile, but it can also read a Dockerfile.

Kubernetes 101

Kubernetes (often shortened to K8s, short for Kubernetes) is a container orchestrator. You tell it the desired state of your app; Kubernetes works continuously to keep reality matching that state.

Hover a component to learn its role.

Core resources

  • Pod — the smallest deployable unit; usually one main container.
  • Deployment — manages a set of identical Pods, handles rolling updates and scaling.
  • Service — stable networking and load balancing across Pods.
  • Namespace — a scope for resources (dev, prod, etc.).

The kubectl mental model

kubectl is your remote control for the cluster Application Programming Interface (API) server. You write declarative YAML (YAML Ain't Markup Language) files and apply them, then use kubectl get / kubectl describe to inspect the result.

Local Cluster Setup

Running Kubernetes on your laptop is the fastest way to learn. kind (Kubernetes in Docker) and minikube are the two most popular tools.

kind

Runs Kubernetes control-plane nodes as Docker containers. Great for continuous integration (CI) and multi-node testing.

  • Needs Docker installed
  • Fast cluster creation
  • Easy multi-node clusters

minikube

Runs a single-node or multi-node cluster in a virtual machine (VM) or container. Lots of built-in addons.

  • Can use Docker, Podman, Hyper-V, VirtualBox, etc.
  • Driver-agnostic
  • Great for beginners

What happens under the hood

  1. Build — Docker/Podman creates image layers and tags the result.
  2. Load — kind load docker-image or minikube image load puts the image inside the cluster.
  3. Apply — kubectl apply -f app.yaml sends desired state to the Application Programming Interface (API) server.
  4. Schedule — the scheduler picks a node; the kubelet starts the container.
  5. Expose — the Service gives Pods a stable Internet Protocol (IP) address and port.
  6. Access — kubectl port-forward lets you reach the app from localhost.
