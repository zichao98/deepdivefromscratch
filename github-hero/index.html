The big picture

Git is your time machine. GitHub is its home on the internet.

Use Git on your computer to track changes. Use GitHub to back up the project, share it, review it, and work with others.

💻

Your computer

The local project folder where you edit code and make commits.

⏱

Git commits

Named snapshots of your project. You can compare or restore them later.

☁

GitHub repository

The remote copy of your project on GitHub, often called the “repo.”

Level 1

Set up GitHub once.

These are the only essentials needed before you share a project.

1. Create a GitHub account

Visit github.com/signup. Pick a professional username; it will appear in your project URLs and commits.

2. Install Git

Windows: install Git for Windows. Open PowerShell and run git --version to confirm it works.

3. Tell Git who you are

Git adds this author name and email to your commits. Do this once per computer.

PowerShell
git config --global user.name "Your Name"
git config --global user.email "you@example.com"

4. Create a repository

On GitHub, click + → New repository. Give it a name and choose Private for personal work or Public to share openly. For an existing local project, do not initialize it with a README.

Level 2

Upload your project to GitHub.

Choose the path that matches where your files are right now.

Best for code projects: open PowerShell inside the project folder. Replace the URL with the one GitHub gives your new repository.
PowerShell
# do this inside your project folder
git init
git add --all
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPO.git
git push -u origin main

Use the web uploader

Open a GitHub repository, choose Add file → Upload files, drag files in, then click Commit changes.

Know the limitation

It is excellent for a few files, but the terminal workflow is better for regular updates because it preserves your project history.

PowerShell
mkdir my-project
Set-Location my-project
git init
'Hello, GitHub!' | Set-Content README.md
git add README.md
git commit -m "Add project README"

Collaborate without fear.

🍴

Fork

A personal GitHub copy of someone else’s repository. You can experiment freely without touching the original.

🌿

Branch

An isolated line of work. Create one for a feature or fix so the main branch stays stable.

🔁

Pull request

A proposal to merge your branch into another branch. It is where people review, discuss, and approve changes.

Everyday collaboration
# after cloning your fork, make your own branch
git checkout -b add-login-page
git add --all
git commit -m "Add login page"
git push -u origin add-login-page
# then open GitHub and click “Compare & pull request”

Reference

Vocabulary you will actually use.

Repository / repo
A project folder plus its complete Git history.
Commit
A saved snapshot of changes, with a short message explaining what changed.
Clone
Download a GitHub repository to your computer with its history.
Remote / origin
A named GitHub destination. By convention, origin is the main remote repository.
Pull
Download changes from GitHub and apply them to your local project.
Push
Upload your local commits to GitHub.
.gitignore
A file that prevents secrets, virtual environments, generated files, or local data from being committed.
Security rule: never commit passwords, API keys, tokens, or `.env` files. Add them to `.gitignore` first. If a secret reaches GitHub, rotate it immediately—even if you delete the file later.
